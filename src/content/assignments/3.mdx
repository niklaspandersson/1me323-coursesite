I denna uppgift ska du bygga en turneringsapplikation där deltagare tävlar mot varandra i ett utslagssystem. Deltagardata hämtas från en JSON-fil med `fetch`, modelleras med JavaScript-klasser, och en visuell turnering renderas dynamiskt med `createElement()`. Användaren driver turneringen framåt genom att simulera matcher.

### Förberedelser

Skapa en ny mapp `assignment3` i din `assignments`-mapp.

```

├── ...
└── assignment3/
```

* Lägg in information om uppgiften i datastrukturen i `assignments.js` så att den visas på startsidan.

Välj **ett** tema för din turnering och använd det färdiga datasetet nedan. Du får även hitta på ett eget tema, men deltagarna ska ha **minst fyra numeriska stats** och minst 2 deltagare med ofullständig data.

### Krav

#### Deltagardata (JSON)

* Skapa en JSON-fil (t.ex. `contestants.json`) med en array av **8 deltagare**.
* Varje deltagare ska ha **minst** följande egenskaper:
  * `id` — Unikt id (t.ex. `"r-001"`)
  * `name` — Deltagarens namn
  * `image` — Sökväg till en bild
  * `stats` — Ett objekt med **minst 4 numeriska egenskaper** (t.ex. `{ "armor": 7, "firepower": 9, ... }`)
  * `specialty` — En kort beskrivning av deltagarens specialförmåga
* **Minst 2 deltagare** ska ha ofullständig data — t.ex. `catchphrase: null`, en stat satt till `null` (oprövad nykomling), eller saknad `backstory`.
* JSON-filen ska hämtas med `fetch`, **inte** importeras som en JavaScript-modul.

#### Klass för match

Varje deltagare i JSON-datan är ett vanligt objekt — det behövs ingen klass för dem. Däremot har en *match* ett tydligt tillstånd som förändras: den har två deltagare, den kan spelas, och den har en vinnare. Det gör den till en bra kandidat för en klass.

* Skapa en `Match`-klass som modellerar en match mellan två deltagare.
* **Privata fält** (`#`) för de två deltagarna och vinnaren — de ska inte kunna ändras utifrån.
* **Getters** för att läsa deltagarna, vinnaren, och om matchen är spelad (`isPlayed`).
* En **metod** `compete()` som avgör vinnaren av matchen (se nedan).
* Hantera saknade/null-värden med `?.` och `??` — t.ex. en stat som är `null` får ett standardvärde.

#### Matchlogik

* Metoden `compete()` ska jämföra de två deltagarnas stats och avgöra en vinnare.
* **Viktat slumpmässigt resultat** — den starkare deltagaren ska ha högre sannolikhet att vinna, men den svagare ska alltid ha en chans. En match får alltså **inte** vara helt förutbestämd av datan.
* Försök komma på en egen algoritm! Tänk på: hur räknar du ut vem som är "starkare"? Hur gör du så att slumpen fortfarande spelar roll?

<summary><strong>Exempelimplementation (Robotarenan)</strong> — Kika här om du kör fast</summary>

Här är **ett** sätt att lösa det på med robottema. Du får använda denna lösning, men försök gärna hitta på en egen variant som passar ditt tema.

Idén: Först avgörs vilken robot som tröttnar snabbast genom att jämföra **snabbhet mot batteri** — en snabb robot med dåligt batteri sliter ut sig. Den utmattningsfaktorn påverkar sedan huvudduellen: **pansar mot eldkraft**.

```js
compete () {
  const a = this.#contestantA.stats
  const b = this.#contestantB.stats

  // Steg 1: Utmattning — snabbhet kostar batteri.
  // En snabb robot med svagt batteri tröttnar fortare.
  const fatigueA = (a.agility ?? 5) - (a.battery ?? 5)
  const fatigueB = (b.agility ?? 5) - (b.battery ?? 5)

  // Steg 2: Stridsvärde — eldkraft mot motståndarens pansar.
  // Draget minskas av utmattning (en trött robot slåss sämre).
  const attackA = (a.firepower ?? 5) - (b.armor ?? 5) * 0.5 - fatigueA
  const attackB = (b.firepower ?? 5) - (a.armor ?? 5) * 0.5 - fatigueB

  // Steg 3: Omvandla till en sannolikhet mellan 0 och 1.
  // Skillnaden skalas ned så att även en svagare robot har chans.
  const advantage = (attackA - attackB) / 10
  const chanceA = 0.5 + advantage  // t.ex. 0.65 om A har ett övertag

  // Steg 4: Slumpen avgör!
  const roll = Math.random()
  this.#winner = roll < chanceA ? this.#contestantA : this.#contestantB

  return this.#winner
}
```

Matchen sker alltså i *två steg* — först utmattning, sedan strid — vilket gör att alla fyra stats spelar roll. Men `Math.random()` avgör i slutändan, så även en underdog kan vinna.

#### Turneringsflöde

* **8 deltagare → Kvartsfinal (4 matcher) → Semifinal (2 matcher) → Final → Mästare**
* Vid start: hämta JSON → `map()` deltagarna till `Match`-instanser (par om två) → rendera första rundan.
* Efter varje runda: hämta vinnarna → `map()` till nya `Match`-instanser → rendera nästa runda.
* Använd `find()` för att slå upp deltagare på `id` vid behov (t.ex. vid återställning från localStorage).

#### Rendering

* All HTML ska skapas dynamiskt med `createElement()` — inga deltagare eller matcher hårdkodade i HTML.
* Varje match visas som ett kort/block med båda deltagarnas namn, bild och stats.
* En knapp per match ("Simulera match") eller per runda ("Simulera runda") driver turneringen framåt.
* Vinnare markeras visuellt. Förlorare tonas ned eller markeras.
* Mästaren får en tydlig visuell markering vid turneringens slut.

#### Hantering av saknade värden

* Använd **optional chaining** (`?.`) och **nullish coalescing** (`??`) för att hantera deltagare med ofullständig data.
* Exempel: `contestant.catchphrase ?? "Inget slagord..."` eller `contestant.stats?.agility ?? 5`.
* I `Match`-klassen: använd `??` för att ge null-stats ett standardvärde vid beräkning av totalstyrka.

#### Persistens med localStorage

* Turneringens tillstånd (vilka som vunnit varje runda) ska sparas i `localStorage`.
* Vid omladdning: kontrollera om det finns ett sparat tillstånd och återställ turneringen.
* En knapp för att starta om turneringen (rensar `localStorage` och börjar om).

#### HTML och CSS

* En `index.html` med header, global navigation (från uppgift 1), och en container för turneringen.
* Separat CSS-fil — turneringen ska ha en tydlig visuell struktur där rundorna syns (t.ex. kolumner eller sektioner).
* Sidan behöver bara fungera på desktop.

#### Kodkvalitet

* Välstrukturerad kod uppdelad i logiska funktioner och gärna separata filer/moduler.
* Beskrivande namn på variabler och funktioner.
* Arrow functions ska användas för callbacks och korta funktioner.

### Tips

* Börja med att kopiera in JSON-filen och skapa `Match`-klassen. Testa i konsolen att `compete()` fungerar innan du bygger vidare.
* Bygg bracket-layouten i HTML/CSS först (hårdkodat), så du vet hur det ska se ut — byt sedan till dynamisk rendering.
* Implementera en runda i taget. Få kvartsfinalen att fungera helt innan du går vidare till semifinalen.
* Testa `localStorage` tidigt — det är lättare att bygga in från början än att lägga till i efterhand.
